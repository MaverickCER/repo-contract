validateExceptionPolicyConfig() function

Validates an entire ExceptionPolicyConfig's shape -- every group's default and every entry in its rules must be a well-formed ExceptionPolicy (see validateExceptionPolicyValue), and no group's rules may use the literal "*" as a key. A literal "*" key is always a mistake, never an intentional blanket policy: resolveExceptionPolicy's own blanket-category handling is triggered by the *input* category being "*", not by a "*" entry in rules -- a "*" rules key would instead be consulted only as an ordinary minimatch glob, which matches the literal one-character string "*" as a *target*, not as a wildcard pattern matching every real category name (minimatch("*", pattern) truthiness depends on pattern, not the other way around) -- see resolveExceptionPolicy's own doc comment, case 1, for the failure mode this prevents.
